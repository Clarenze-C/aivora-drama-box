=== B. NEW FINDINGS ===

B1. Severity: Major. Affected scope: R5b lines 63-73, and R5a line 46-48 (the READY definition).
The ready endpoint's state machine crosses two processes with unclear ownership, and its most complex feature may be unnecessary. Verified: the gateway is a deliberately tiny security component (token check + proxy, byte-identical across two images, guarded by test_canary_gateway.py:29-33); provision.py as it stands prints one JSON status line and writes no state file, no per-file byte counts, and no failing-file names — so the spec's state.json obligations (line 41-42) silently require modifying provision.py (which has its own guard test, test_provision.py) or degrading the fields start.sh can produce. Separately, READY = "provisioned AND ComfyUI answering" requires the gateway to probe 127.0.0.1:8189 — an HTTP-client dependency added to the security component. Simplicity rationale: three unspecified ownership decisions in one component; the minimal design keeps the gateway dumb (serve the state file verbatim behind the token check) and learns "ComfyUI answering" where a boot-window client retry already must exist anyway (the first attest/object_info, canary-style). Suggestion: one sentence naming the state-file owner (start.sh wrapping provision.py, or provision.py gaining a --state-file flag), and either drop comfy_up from the gateway or explicitly accept the probe with its failure semantics.

B2. Severity: Major. Affected scope: §4 lines 157-168 and R5b lines 71-73.
Experiment-level retry semantics are absent and they interact with the budget architecture. With container-disk weights and the one-open-acquisition index (0026:46), screen and full are separate pods, each paying boot + a full 42 GB download; every PROVISION_FAILED/BOOT_TIMEOUT/ambiguity abort forfeits the download and pays a fresh cold start (~25 min GPU ≈ $0.36 each at $0.86/h). The spec never says whether `execute --phase screen` re-runs under the same authorization, whether the ≤ 2 h quote window survives a failed attempt (two cold starts ≈ 50 min of the window's budget makes multi-attempt the norm, not the edge), or how many attempts fit inside 4 GPU-h. Simplicity rationale: this is not a reliability nicety to engineer around with in-pod retries (see A9); it is one unstated paragraph that determines whether the $8 envelope is actually sufficient under first-run reality. Suggestion: add a short failure-and-retry subsection: what each failure leaves durable (acquisition state, incident, holds), what the operator re-runs, quote/authorization validity across attempts, and the ~28 MB/s sustained-throughput assumption behind boot_budget=25 min.

B3. Severity: Nit. Affected scope: R5a lines 53-56 (storage decision), §4.
The double 42 GB download per experiment is a direct consequence of the container-disk + no-volume decision and should be stated as such where the decision is made (it is the compute line's biggest variance driver). Acceptable for a one-shot experiment — but it belongs in the R5a alternatives note (A8), not discovered at run time.

B4. Severity: Nit. Affected scope: R5a line 50-52 (env flag placement).
"The flag value is part of the attested create intent" and RR-T4's "refused without it for this world" push benchmark-world policy into the rendering transport if done naively. Verified the env payload is built at runpod_transport.py:382-391 from the request/attestation objects. Simplicity rationale: right placement is the existing request/attestation data (the transport stays world-agnostic) with the refusal enforced at intent validation on the benchmark side. One sentence naming the layer.

B5. Severity: Nit. Affected scope: R5d lines 113-150.
The tool is justified as assembly, but its boundary with the existing benchmark CLI (prepare/seal/preflight/execute/export per FM §1) is unstated, and "refuses on any drift" is undefined across 10+ tables (which fields may legitimately evolve — e.g. rights eligible_until — versus which are frozen?). Simplicity rationale: without one boundary sentence ("prepare_run authors and registers; the benchmark CLI remains the only enforcement entry"), the tool grows its own validation copies — the reinventing-the-wheel risk zoom-out #5 already spotted in miniature. Suggestion: state the boundary and define drift (a named frozen-field set per row type).
