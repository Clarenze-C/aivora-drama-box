1. **BLOCKING — A later selection can reuse an old completed job.** [intake.py:716](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:716), [intake.py:991](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:991). Select B, then A, then B again. The third selection reuses B’s completed job; the research trigger key also replays B’s old run. The current Gate 1 proposal stays on A despite the new selection. Include a durable selection revision in both keys, while keeping retries of that revision idempotent.

2. **BLOCKING — Workbench sheet queries can show another owner’s records.** [intake.py:1397](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:1397), [intake.py:1435](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:1435). Prop and location IDs are queried globally, and every workbench queries asset sheets for the shared subject `style`. Two owners using the same subject ID can see each other’s sheet IDs, hashes, and asset IDs; `rows[-1]` also guesses when multiple sheets match. Require provable season provenance for each sheet and label unresolvable matches unknown.

3. **BLOCKING — Missing or disabled research sources do not block dispatch.** [intake.py:531](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:531). A nonempty `allowed_source_ids` passes even when `source_provider_id` is absent or disabled. Intake enqueues a job and candidate generation can spend before research reports unknown source probes. Check the configured provider’s enabled state and required research prices before enqueueing; return typed blockers.

4. **BLOCKING — Several workbench values bypass document verification.** [intake.py:1383](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:1383), [intake.py:1530](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:1530). Raw `EpisodePack` payload determines which prop and location sheets appear; raw wardrobe payload supplies a `/ui/media/{asset_id}` link; prompt summaries also use raw payload. A changed payload with a stale hash can therefore alter the display and route the owner to an unrelated asset they can access. The media route still enforces owner access. Validate and hash-check these records before using their fields; show verification failures as unknown.

5. **BLOCKING — The workbench treats an unverified proposal scope as approved canon.** [intake.py:1230](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:1230), [workbench.html:7](/root/AIVORA/drama-box/microdrama/src/microdrama/review/templates/workbench.html:7). Even a valid `PROPOSED` scope appears under “Approved scope.” Verify the scope hash and label its actual proposal status; show a mismatch as unknown.

6. **NON-BLOCKING — Status can hide the reason an intake is stuck.** [intake.py:820](/root/AIVORA/drama-box/microdrama/src/microdrama/review/intake.py:820), [intake_status.html:19](/root/AIVORA/drama-box/microdrama/src/microdrama/review/templates/intake_status.html:19).
