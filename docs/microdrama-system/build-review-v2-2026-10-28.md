## Verified baseline and interpretation

It has versioned contracts and PostgreSQL state, exact budget reservations, durable jobs, two human approval gates, identity lock, reference and voice services, shot routing, ComfyUI-shaped fake workflows, FFmpeg assembly, captions, three hook cuts, QA with visible unknown coverage, release/account adapters against fixture transports, analytics, and a scheduler-driven mock path. The [remediation record](../../microdrama/evidence/build-review-2026-10-25-remediation.md) documents closure of the previous F01–F09 findings. They are **not reopened** here.

Current code still deliberately refuses live provider operation. T031–T035 have no real evidence, and AT-14 has not run. A successful mock path cannot establish production quality, Thai performance, rights, actual GPU cost, public publishing, or the proposed $10 variable-cost fit. The [offline pilot runbook](../../microdrama/runbooks/pilot.md) states this distinction. The current `README.md` and V1 documents contained stale baseline language; V2 updates must distinguish accepted software history from pending live milestones.

## Acceptance direction

1. **Restore the offline acceptance gate and close each defect before its affected path.** V2-F12 must make `make check` repeatable on any date while preserving the DB's human-session security rule. V2-F01 blocks prop-dependent paid shots; V2-F02 blocks role-correct V2 rendering; V2-F04/F05 block real public scheduling. A bounded generic technical canary may precede the V2 reference resolver, but it cannot certify a narrative episode. Regression tests must exercise composed draft → shot → references → prompt → output and absent-post rearm → scheduler → provider call → verified readback. A schema-only test is insufficient.
2. **Qualify V1 with the smallest Runpod canary before full V2 app rollout.** Record selected rights route, pinned graph/model/GPU, current quote and maximum exposure, reference-controlled output, cold/warm timing, all attempts, actual bill and verified pod shutdown. A manually operated pod proves model/hardware feasibility; the subsequent adapter canary must prove DramaBox's own lease, budget, retry and janitor path.
3. **Build V2 creative contracts and UI against durable state.** The chosen season scope must carry genre promise, character/secret/payoff structure; episode packs must carry visible cast, props, location, story day and wardrobe changes; shots must bind typed versioned assets and state. The app derives percent from persisted accepted work, never optimistic model guesses.
4. **Retain the original constraints.** Original Thai fiction, 180–300 second episodes, maximum 15-second generated shot unit, two routine human approvals, $10 maximum directly attributable variable cost, required rights/capability evidence, and ten-episode reliability qualification still apply.

This review defines required work; it does not certify any live route or claim the V2 implementation exists.
