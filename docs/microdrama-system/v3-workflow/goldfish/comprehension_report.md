## What this proposes

This is the master specification for "Drama Box v3", the next version of an automated microdrama production system that already exists in an offline-mock form. It proposes turning a one-line idea into a 20–30 episode Thai-language vertical-video series (~120 s episodes, released daily at 19:00 Asia/Bangkok to YouTube Shorts, TikTok and Facebook), governed by five human content gates — season-concept LOCK, STORY LOCK, CAST LOCK, Gate 2 (episode approval), TEASER — plus a LAUNCH calendar approval. Production is reorganized around "logical demand IDs" planned at STORY LOCK and resolved to immutable cast/voice/location asset versions at a new season-scoped CAST LOCK, replacing the old episode-1 identity lock created at Gate 2. Every paid provider call follows a hold-budget → effect → record discipline with reconciliation of ambiguous outcomes, all providers have offline fake adapters behind fail-closed live switches, and a Telegram bot notifies (deep links only, never approvals). The work is split into phases A0 and A–G (§15), each getting its own normative phase spec, with acceptance obligations V3-AT-1..17 (pinned v0.1 baseline) plus V3-AT-18..32 (adopted from the Codex critique), an end-to-end composition test, a 30-episode release simulation, and a cost/quota pilot (P0/P1/P2) culminating in PILOT-REPORT.md.

## How the existing system works, per this document

The existing system (as described here and in the linked factmap/pipeline-map) is a FastAPI/Jinja app behind Coolify/Traefik at dramabox.aivora.agency, running an OFFLINE_MOCK composition: fake LLM, source, image/voice generation and publishing adapters, but real local FFmpeg editing, captions and variants. Its pipeline runs intake → Gate 1 concept approval → season bible compilation → daily episode-record creation → episode writing/shot manifests → reference preparation → render dispatch → edit/mix → captions/variants → QA/repair → release packaging → Gate 2 (which today also creates an episode-1 identity lock and requires `source_episode_id` + `release_package_hash`) → scheduling/publishing (mock). V3 keeps the app, gates concept and QA/review machinery, and changes the state model into separate season-planning / season-release / episode-production / episode-release tracks, moves identity locking from Gate 2 to a season CAST LOCK, creates all episode rows at STORY LOCK, and adopts the T031 render transport ("binder", `PikaBindingContext`, 124-frame shots) as the production render path.

Every section, including §15–§19, was paraphrasable; no Blocker findings.
