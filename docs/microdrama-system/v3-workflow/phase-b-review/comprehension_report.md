**What this proposes**

Phase B is the story-planning slice of the v3 rewrite: it builds stepper tabs 1–3 and their two human gates. Tab 1 takes a one-line idea (trend-research "Mode A" is visibly disabled and refused before any write), an LLM job produces 2–3 materially distinct season proposals, and the operator Approves/Revises/Rejects at the LOCK gate — the approved proposal becomes the planning authority. Tab 2 generates a season bible plus an "extension seam" in one LLM call, checked by deterministic and LLM critics, with character tiers (PRINCIPAL/SUPPORTING/EXTRA) derived from actual usage across all packs. Tab 3 plans every episode in order as a full `EpisodePackV3` (scenes, beats with ≤2 speakers, trilingual lines with emotion tags, wardrobe/props/locations referenced only as stable "logical demand IDs" — never assets), maintaining a running continuity state, ending with a deterministic demand list, a season critic, and STORY LOCK, whose Approve creates all N episode rows in one transaction and can later be extended via `create_extension`. All V3 records are append-only sealed documents in a new `v3_story_documents` table; V1/V2 validators, records and consumers stay frozen and refuse V3 input; every LLM call is a resumable `LlmStep` inside a job, unmetered during the pilot. §10–§13 sequence the build into packages B1–B6 (B1 and B5 design notes critiqued first), define twelve offline acceptance tests B-T1..B-T12, record six operator-resolved open questions (3 locations/episode, default 24 episodes, 6-value emotion vocabulary, Opus for proposals, per-episode LLM critic off by default, separate V3 document table), and trace R-1.x–R-3.x and prior findings to sections.

**How the existing system works, per this document**

The legacy system is a V1 research-driven pipeline (trend research, 180–300 s episodes, an identity-lock gate IMP-01 required before the writer runs, and the T039 rule that only the first three episodes are fully scripted — later episodes are map-only outlines) plus a V2 script-maker that stores append-only sealed documents in `v2_contract_documents` with secret/season ledgers, all frozen at contract versions 1.15.0/2.15.0. Planning today binds real asset, wardrobe-assignment, identity-lock and voice IDs, and downstream consumers (directing, rendering, editing, review, community) read V1/V2 packs directly; the release cadence scheduler creates episodes over time. Phase B leaves all of that untouched: V3 code lives in new modules that only import a few pure functions (secret-leak check, `estimate_line_ms`, canonical hashing, injection-resistant framing, originality helpers), the V3 writer opens no asset/identity/voice table, legacy consumers reject V3 episodes with `WORKFLOW_MISMATCH` until their owning phase migrates them, and V3 seasons are invisible to the V1 cadence selector.
