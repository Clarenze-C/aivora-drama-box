## Overall verdict on the architecture after the critic stage

The architecture survives the critic stage intact and is still the right shape: it reuses identity_locks, the GenerationProvider protocol, phase A's jobs/accounts/fence, and B's store pattern; it adds no second job system; picks-as-votes still eliminates selection side state by construction. The critic's one Blocker (no trigger for initial candidate generation) is a real hole but closable inside the existing job and metering mechanisms. What needs steering is the remedy set itself: three consolidated critic fixes (initial generation, pick-kind mapping, derived-asset acceptance) can each be implemented in a way that quietly adds a new mechanism, and one (the lock inode pin) proposes state with no home. Two genuine architecture-level gaps remain that no earlier stage framed correctly: the missing characters seeding step, and C's failure to hook into the contract-delta governance B v0.4 established.

## Residual finding carried forward (new evidence)

**R1. [Major] §2 C-3 (lines 98-100), §3 (line 141), §4 (line 176) — cast_dependency_edges remains a second representation of derivable data, and the A4 contract does not require it.**
No critic-stage finding touched C-3, so it risks being dropped in consolidation. New verification: phase-A-spec.md §7.3 (line 326) defines the DependencyProvider as a registry that computes closures ("the computed closure (`DependencyProvider` registry; phase A wraps `targeted_invalidation` and `invalidated_shot_ids`)") — the contract wants a closure computation, not persisted, addressable edge rows. Both edge kinds are single-parent and derivable from the child's pick_kind plus parent_pick_id (already a C-1 column); §4's staleness rule already computes dependency state from stored columns. Dropping C-3 (a migration, a table, a registration path) and handing A4 a closure computed from parent_pick_id + pick_kind conforms to the A contract and removes a representation that can drift. If the C1 critique decides the edges must persist, the spec must say why A4's registry cannot take a computed closure.

## New and updated findings

**1. [Major] §1.2 (lines 52-54), §4 (lines 158-173), §12 C4 — the initial-generation trigger fix (critic Blocker 1) must not add a new enqueue path or a fourth operator verb.**
The critic's remedy menu offers a per-item/per-category "Generate candidates" operator action or a bounded initial batch after setup-budget approval. At architecture altitude the batch is strictly simpler and more coherent: the forecast already priced exactly that volume, the operator approved exactly that money (AC-13, O-C3), so spending it needs no new consent construct. The batch is just N ordinary `cast_v3.generate` job rows enqueued at one moment — the logical work ID `cast-gen:<season>:<pick>:<attempt>` (§10) already carries the attempt and gives idempotency. A per-item "Generate candidates" action adds a fourth operator verb (next to vote, re-roll, generate next), a new primary action per grid, and operator toil across dozens of items to materialize a grid the forecast promised. Equally, no "campaign manager" or batch-orchestration component: fairness batching (§5) already bounds dispatch. The fix is one sentence in §1.2/§4 plus a C-T3 clause.

**2. [Major] §2 C-1 (line 98), §8 step 3 (line 325) — the pick-kind remedy should follow B's C-B1 pattern (extend the CHECKs honestly) rather than publish a permanent lossy 12-to-5 mapping.**
All four reviewers found the missing mapping; my verdict differs from the critics' primary remedy ("publish the mapping table"). A many-to-few mapping forces PROP, EXTRAS_LOOK, SHEET_VIEW, EXPRESSION, MUSIC_LIB and SFX_LIB to masquerade as FACE/VOICE/WARDROBE/LOCATION/STYLE, and every kind-keyed reader (V1's cast_package_assets, D's cast_binding) then lives with a translation rule forever. The simpler long-run remedy is the mechanism B v0.4 §2.4 established for exactly this case: a phase crossing an A-enforced contract owns the delta in its own migration range. Map only where semantics are true (FACE→FACE, OUTFIT/APPEARANCE_STATE→WARDROBE, LOCATION_MASTER/COVERAGE→LOCATION, VOICE_NEUTRAL→VOICE) and extend the two CHECKs (reference_versions.ref_kind, identity_lock_assets.asset_kind) with honest values for the rest, using the version-aware constraint pattern C-7 already establishes so V1 rows and V1 writers stay on the five-kind vocabulary. One-time schema honesty beats a permanent translation layer. Whichever way is chosen, the design must also pin ref_key namespacing: if SHEET_VIEW and the character's FACE both land on ref_kind FACE with the same ref_key, their candidate sets merge (§4 defines candidates as versions for `(target_ref_kind, target_ref_key)`) — that collision is where a naive mapping silently breaks the picks engine. Load-bearing for C1, the critiqued-first migrations package.

**3. [Major] Header line 11, §2 (line 88), §12 C1 — the stale B pin hides a governance boundary: C never hooks into B v0.4's C-B1 contract-delta mechanism.**
The structural/style finding (re-pin v0.3 to v0.4) is correct but understated. B v0.4 §2.4 is not just a version bump: it establishes a first-class contract-delta register (D1-D4) plus a standing rule that any identifier crossing an A-phase enforced contract is checked against that contract's enforced vocabulary before the phase's first note is accepted. C crosses at least three A-enforced contracts: jobs.queue CHECK (C-8), identity_locks NOT NULLs (C-7), and whatever finding 2 lands on. C1 is already "critiqued first (migrations)", but the spec never says C's crossings are enumerated and validated the C-B1 way. The fix is cheap and adds no mechanism: re-pin to v0.4 and add one C-B1-style table (or line) in §2 stating C's contract crossings and that each is checked against the enforced vocabulary before the C1 note is accepted. Without it, each C migration improvises its own conformance argument against contracts A owns.

**4. [Major] §5 (lines 185-196), §12 C3 — GenerationAdapter reuse is now load-bearing, not cosmetic (upgrade of initial zoom-out finding 7 from Nit).**
The critic stage verified that the cache-key collision fix (critic Major 5) lives inside the existing adapter machinery: build_image_request carries the seed (generation.py:415-434) and the cache key is derived from the spec including it (service.py:890-916). C3 must engage GenerationAdapter's internals regardless of what the spec says. If C3 writes a parallel driver, it must re-solve reservation, rights, seed rotation and cache-key uniqueness beside the existing implementation — two divergence-prone copies of the paid-generation discipline. The spec should state C3 wraps/extends GenerationAdapter (episode-scoped to season/step_04-scoped) and reuses check_rights/build_image_request. This also constrains the critic 5 fix: rotate the seed in the request (vary the input), never weaken the UNIQUE (season_id, cache_key) constraint — that constraint is the existing duplicate guard and stays.

**5. [Major] §3 (line 138), §4 (lines 177-179), §8 (lines 310-313) — derived-asset acceptance (critic Major 3) should be recorded as vote appends, not a new acceptance mechanism.**
Critic Major 3 correctly demands a per-pick_kind table splitting human-pick kinds from derived kinds, with derived kinds accepted at the CAST review. Guard the fix: "acceptance" should be a bulk operator action writing ordinary append-only cast_pick_votes rows (session-marked), not a new acceptance record type or second state machine. §4 already projects ACCEPTED "at CAST review"; keeping one selection mechanism (latest vote) for both kind classes means the lock condition differs only in who votes and when — one mechanism, two policies. A separate acceptance construct would duplicate the vote path (table, UI action, staleness interaction) for no capability gain.

**6. [Nit] §5 (lines 197-211), O-C5 — the lock inode pin (critic Major 6) is the right mitigation but needs a home in an existing record, not a new mechanism.**
The silent-loss scenario (an ARISA redeploy swapping the lock file's inode) is real, and a pinned-inode comparison on acquire is a few lines inside the existing lock helper. But "pin at qualification" implies persisted state and a re-pin ritual; housing it in a new lock-integrity record plus an alerting subsystem would be over-engineering. A's provider_qualifications (phase-A-spec §9 item 4) already holds provider, configuration hash, evidence ref, qualified_at and expires_at — the pinned inode belongs there, and expires_at provides the natural re-qualification cadence after ARISA upgrades. Proportionality: a mid-hold file swap overlaps at most one Drama batch (≤120 s per the fairness defaults), so qualification-time plus per-acquire checking is enough; anything more (watchdogs, file watchers) is YAGNI. Bind-mount fail-closed behavior already falls out of opening read-only and never creating, which §5 states.

**7. [Nit] §3 (lines 123-141), §8 step 4 (line 327) — characters seeding (critic Major 7): seed at derivation with demand-ID keys; no character-lineage machinery.**
The missing component is real (voices.character_id is NOT NULL; lock step 4 freezes characters). Minimal fix is one sentence: derive_pick_items (C2) upserts characters rows keyed by the character demand ID, matching the §1.10 canonical-ID discipline. The critic's phrase "including promoted extras roles and their merge lineage" should not be read as an invitation for a new lineage table — promotion facts already live in B's records; reference them, don't duplicate them.

**8. [Nit] §9 (lines 362-368 and 375-378), §12 C10 — one image inspection seam plus recorded human checks; do not generalize into multi-modal detection now.**
Consolidates the OCR/branding fallback gap (initial zoom-out finding 5) with the YuE2 vocal-leakage gap (critic Nit 16). Both fixes should take the shape the spec already gives likeness: a recorded human check until a qualified detector exists (O-2). OutputInspectionProvider stays an image-frame seam — its named consumers (D/F thumbnails, clip-sampled frames) are images, and no OCR or audio detectors exist in the codebase today. Building audio-detector plumbing or a generalized multi-modal inspection framework in C10 would be detector infrastructure with no detectors.

**9. [Nit] §1.12 (lines 82-86), §2 C-8 (line 105) — lane justification correction (self-correction of my earlier no-finding).**
My initial pass cleared the four new queue lanes as "master-mandated"; on re-reading, SPEC-v3 §10.2 mandates the shared lock and "the queue policy" but names no lanes — the four-lane split is C's own choice, and each lane costs the four-point checklist (CHECK, policy ownership, worker set, generated contracts). image (GPU-bound provider work) and voice_intake (isolated untrusted-byte decode away from production workers) have clear boundary rationales. music and sfx each carry roughly one job per season; either justify their separation in one sentence (provider-class isolation for metering/concurrency) or collapse them into one lane.
