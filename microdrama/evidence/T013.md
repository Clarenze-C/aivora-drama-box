- Open items (honest):
  - a crash *between* `queue_prompt` returning and the persist, retried inside the
    attempt deadline, could queue a duplicate prompt: the client-token pre-check makes
    `submit` refuse to re-dispatch an existing operation, so the window needs a worker
    retry of a crashed *in-flight* begin; job-lease exclusivity plus pod-interval
    accounting bound the cost, and past the deadline the attempt is UNKNOWN (never
    blindly rerendered). Server-side prompt lookup by client token would close it fully
    (contract proposal below).
  - `MISSING_REQUIRED_OUTPUT`/`OUTPUT_INCOMPLETE` details are not persisted beyond the
    error code (the `ProviderOperationResult` contract has no detail field).
- Contract proposals (for the guardian, not edited):
  1. `ComfyClient` has no reconcile-by-client-token route (unlike `GenerationProvider`).
     Adding one (e.g. `prompts_for_client(client_id)`) would let UNKNOWN submit-crash
     cases self-heal instead of requiring operator reconciliation.
  2. `ProviderOperationResult` lacks a free-text `detail`; failure diagnostics now stop
     at the error code.
- Integration notes: `build_comfy_render_service(db, budget, client, clock, ids,
  settings, config, store)` (config `None` → mock price offline, unknown price → refuses
  dispatch); `ComfyRenderService.reserve_attempt(episode_id=…, semantic_key=…) ->
  Reservation` must run before the `RenderRequest` is built (its id goes into the
  request); `submit(request, job_id=…)` requires a durable `render.shot` job whose input
  is the exact request (JobService.enqueue validates it); `poll(operation_id)` /
  `status(operation_id)` drive WAITING_EXTERNAL. T014 consumes:
  `rendering.workflows.PRESET_TEMPLATES` (preset → template mapping it should own or
  extend), `bind_workflow`/`template_sha256` (pinned `workflow_sha256`),
  `render_id_for(semantic_key)` for deterministic attempt ids, and
  `ComfyRenderConfig(price, timeout_ms, poll_after_ms, required_media_kinds)`.
