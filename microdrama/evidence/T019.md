- Idempotency/determinism: QA plan id = uuid5 over (episode, qa cycle, round);

  cycle. Feedback plan id = uuid5 over the REVISE approval event (the DB's

  a COMPLETED plan replays its stored outcome event with no duplicate effects

  cannot re-execute. Preference rule ids are deterministic per (season, key,
  version) and identical remember-calls replay the stored version. Findings the
  plan covers flip resolution OPEN→RESOLVED.
