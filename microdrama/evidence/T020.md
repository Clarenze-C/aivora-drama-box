## Acceptance evidence (task_breakdown §5 T020 — AT-09)

- **No release before approval**: `schedule_release` refuses every episode without an
  APPROVED, approval-bound package (review invariant: one APPROVED per episode, hash-
  bound decision); each slot row carries the package id and approval event, and
  `submit_slot` re-verifies the command names that exact package (id + hash), that
  approval event, and the pinned media
  (`test_command_naming_a_different_package_is_refused`,
  `test_command_with_a_foreign_approval_event_is_refused`,
  `test_schedule_for_an_episode_without_an_approved_package_is_refused`).
- **CTA dependencies wait for the actual target**: a slot whose `depends_on` names
  another slot cannot submit until that slot is `PUBLISHED_VERIFIED` **with a live
  external id** — a merely-submitted dependency still blocks
  (`test_dependency_waits_for_the_actual_verified_target`: refused while target is
  SCHEDULED, refused again while SUBMITTED, released exactly after verification).
  Scope shape is validated at schedule time (unknown dependency → Conflict, cycle →
  Conflict via Kahn, self-dependency refused by the contract model).
- **Duplicate slots rejected**: `dedupe_key` UNIQUE (DB) + slot-tuple UNIQUE
  (migration 0005) + idempotent same-package replay returning the existing rows and a
  cross-package schedule refused
  (`test_approved_package_becomes_scheduled_slot_rows`,
  `test_schedule_is_idempotent_for_the_same_package`,
  `test_duplicate_slot_key_across_packages_is_rejected_by_the_database`).
- **Crash after provider submit cannot blindly repeat**: every submit is a durable
  `provider_ops.begin` (PENDING_SUBMIT) committed BEFORE the adapter call, with the
  deterministic `client_token` on the slot row; ambiguous adapter outcomes (TIMEOUT_*
  scenarios, mid-call crashes) land the operation in UNKNOWN and the slot in
  NEEDS_RECONCILIATION, where a further `submit_slot` is refused;
  `reconcile_slot` adopts a found post by external id (op UNKNOWN→SUBMITTED with the
  id persisted in the same tx) and only a reconcile that proves the post absent
  re-arms the SAME client token via `provider_ops.resubmit_allowed` — never a new
  token, never a blind resubmit — capped at 3 attempts
  (`ATTEMPT_CAP_REACHED`). Provider-op crash-safety ordering itself is proven by
  `test_crash_between_begin_and_send_leaves_recoverable_state`: a process death
  between begin and send leaves PENDING_SUBMIT + SCHEDULED, and the retry with the
  same token creates exactly one post.
- **Missing required destination prevents full-release qualification**: the episode
  reaches PUBLISHED_VERIFIED only when every required slot is PUBLISHED_VERIFIED; a
  HELD or FAILED required slot surfaces in `release_view` blockers with the episode
  held (HELD is explicitly "not a failure of the episode"; no outcome is forced),
  while a held/failed OPTIONAL slot never blocks
  (`test_held_required_slot_blocks_full_release_qualification`,
  `test_held_optional_slot_does_not_block`,
  `test_failed_required_slot_is_a_blocker_not_an_episode_failure`,
  `test_all_required_verified_reports_ready`).
- **DST/late-window/permission/readback unknown tests**:
  - DST: schedules are `ScheduleInstant` (gap rejected, overlap needs fold — pinned by
    `test_dst_gap_schedule_is_refused_at_contract_level` /
    `test_dst_overlap_requires_explicit_fold`); poll/reconcile rebuild the schedule
    from the row, trying fold None first so the rebuilt command hashes identically to
    the original (`test_publication_command_round_trips_through_the_durable_row`).
  - Late window: a window that already opened submits immediately; a future window
    submits only through the provider's SCHEDULE operation support, else PolicyDenied
    until the window opens
    (`test_future_window_without_schedule_support_is_refused`).
  - Permission: DENIED_PERMISSION / TOKEN_EXPIRED map to a terminal FAILED slot with
    the error code recorded and nothing published; capability/disclosure destination
    blockers (disabled capability, unsupported AI disclosure, stale capability record)
    HOLD the slot with a typed blocker and clear only when the destination check
    passes again (`retry_held_slot`).
  - Readback unknown: PUBLISHED_VERIFIED is readback-gated — the readback must prove
    `visible=True` and every declared disclosure visible; a blind or partial readback
    leaves the slot PROCESSING with the unverified fields recorded, never verified
    (`test_unknown_readback_is_a_gap_not_a_verification`,
    `test_partial_disclosure_readback_does_not_verify`); the DB CHECK pins
    external_id + verified_at on every PUBLISHED_VERIFIED row.
- **Immutable media / current metadata policy**: the slot pins asset id + sha at
  schedule time (DB trigger-immutable); the command must repeat them exactly, the
  stored object must still hash to the pin (tamper → refuse before any adapter call),
  and metadata moves only through append-only `metadata_versions` rows (content
  trigger-immutable, delete forbidden, one current applied version, first version at
  a deterministic id the command must name; later commands must name the current
  version; substantive vs cosmetic changes distinguished; rollback records
  `rollback_of`) — `test_metadata_versions.py` (7 tests) +
  `test_media_is_resolved_from_the_store_not_caller_bytes`.
- **Rollback state**: `cancel_slot` is the operator rollback for slots that never
  reached the provider (CANCELLED, reason recorded); a slot with a live external id
  refuses cancel and points at management actions; terminal slots refuse cancel
  (`test_qualification.py`).
- **Provider protocol**: adapters implement `PublisherAdapter` only — no local
  approval/budget logic; the frozen scenario matrix (accepted/denied/429/timeout-
  ambiguous ×2/replayed) is contract-tested through the service surface in
  `tests/contract/publishing/test_publishing_contract.py` (13 tests), including the
  replay dedupe (two job runs, one provider operation, one post) and the
  unmetered-kinds/job-spec pins T021–T024 build against. Live publishing remains
  disabled everywhere (OFFLINE_MOCK; fake adapters only).
