## Declaration truth (the packet's core honesty test) — DECIDED: UNSUPPORTED

The documented Instagram content-publishing surface (`POST /{ig-user-id}/media`
container create, `GET /{container-id}?fields=status_code`,
`POST /{ig-user-id}/media_publish`, `GET /{ig-media-id}` media node) provides **no
parameter to set a synthetic-media/AI label at publish time and no field to read one
back**. Meta's documented labelling mechanisms (automatic detection, the in-app
self-label toggle, C2PA Content Credentials embedded in the file) are not reachable
through the publishing API: none can be SET by this adapter and none can be READ
BACK. Therefore:

- `AI_DISCLOSURE = UNSUPPORTED` (frozen snapshot, `capabilities.py`), and
  `supported_disclosures = []` on **every** record this lane builds — fixture
  variant included (fixture evidence never upgrades a claim).
- Under MD-015 (every `ReleaseSlotPlan` must declare `AI_GENERATED_CONTENT`),
  `PublishingService._check_capability` HELDs **every** Instagram slot with
  `UNSUPPORTED_DISCLOSURE` before any provider operation begins. That is the
  documented outcome this lane ships and tests e2e — it is NOT papered over with an
  invented disclosure mechanism.
- Consequence for the frozen scenario matrix: through the service, every row
  (ACCEPTED/DENIED_PERMISSION/TOKEN_EXPIRED/RATE_LIMITED/TIMEOUT_CREATED/
  TIMEOUT_NOT_CREATED) lands HELD/UNSUPPORTED_DISCLOSURE with zero provider
  operations and the scripted platform response never consumed
  (`test_scenario_matrix_through_the_service_lands_held`, 6 rows). The scenario
  mechanics themselves are contract-pinned at the adapter boundary, the only
  boundary where the disclosure hold does not preempt them
  (`test_adapter_scenario_matrix_maps_provider_responses`, 6 rows, plus the
  TIMEOUT_CREATED/TIMEOUT_NOT_CREATED reconcile splits).
- The readback truth is pinned both ways: the media node readback reports
  `visible=True` but `disclosures_visible=[]` with `"disclosures"` in
  `unverified_fields` — so even a post that publishes can never VERIFY an AI
  disclosure through this API (`test_full_offline_adapter_flow_publishes_but_disclosure_stays_unverified`,
  `test_readback_is_visible_but_disclosure_blind`).
- Upgrade path: if a verified mechanism appears (a documented API field, or a
  C2PA-embed + readback proof T032 can actually test), the snapshot entry and
  `SUPPORTED_DISCLOSURES` change in `capabilities.py` with new evidence — nothing
  else moves.

## Acceptance evidence (task_breakdown §5 T023 row)

- **Professional account / login-flow capabilities**: the platform requires an
  Instagram Business or Creator account (linked to a Facebook Page); personal
  accounts cannot use the publishing API. Encoded twice: `account_type` truth from
  the transport account query (PERSONAL ⇒ record disabled ⇒ service hold
  `CAPABILITY_UNAVAILABLE`, `test_personal_account_record_is_disabled`,
  `test_personal_account_route_is_unavailable`) and an adapter-level submit refusal
  `NOT_PROFESSIONAL_ACCOUNT` before any wire call
  (`test_non_professional_account_is_refused`). MEDIA_CREATOR (Creator) counts as
  professional (`test_creator_account_is_professional`). The login-flow permission
  (`instagram_content_publish`, app review) is documented as capability evidence
  (permission ref in `OPERATION_SNAPSHOT`); DENIED_PERMISSION maps Graph error code
  10 → `PERMISSION_DENIED`, TOKEN_EXPIRED maps code 190 → `TOKEN_EXPIRED`.
- **Container/process/publish flow**: submit creates the container (SUBMITTED,
  `igc-*` external id); status maps container `in_progress` → PROCESSING,
  `finished` → publish (`media_publish`) → PUBLISHED_VERIFIED with the published
  media id (`igm-*`) + permalink; `error`/`expired` → FAILED non-transient
  (`test_container_progression_submitted_processing_published`,
  `test_container_error_fails_the_slot`, `test_container_expired_fails_the_slot`).
  media_publish happens exactly once per container (idempotent re-poll by either id
  shape answers from the adapter ledger, `test_repoll_is_idempotent_by_either_id`).
  Ambiguous submits: TIMEOUT_CREATED raises NeedsReconciliation with the container
  id retained for reconcile-found; TIMEOUT_NOT_CREATED reconciles absent; replayed
  submits dedupe by client_token with exactly one container creation
  (`test_replayed_submit_is_deduplicated_by_client_token`).
- **Required declarations/readback**: see the declaration-truth section above — the
  required AI disclosure cannot be set or read back on this platform; the honest
  outcome (HELD/UNSUPPORTED_DISCLOSURE, readback disclosure-blind) is the pinned
  e2e path through the REAL Gate 2 + schedule + submit flow
  (`test_submit_holds_with_unsupported_disclosure`,
  `test_held_slot_blocks_full_release_qualification`,
  `test_replayed_held_submit_conflicts_without_touching_the_destination`,
  `test_retry_held_slot_still_blocked_by_the_disclosure_truth`).
- **Supported metadata/insights actions**: `POST /{ig-media-id}` caption update is
  documented for image media only — every container this lane publishes is video,

  INSIGHTS = SUPPORTED_DOCUMENTED; the documented insights edge is exposed as the

- **Routing/limits from slot_kind**: PROMO_CUT/HOOK → REELS containers,

## Implementation limits / honest unknowns

- Adapter-ledger dedupe/reconcile: the ledgers live on the adapter instance (the
  fixture stand-in for "inspect the account"); a real reconcile (T031+) must
  discover posts by listing account media, not by in-memory maps.
- Duration enforcement needs a caller-supplied `duration_lookup` (the command
  carries no MediaInfo); unknown duration defers to server-side container
  validation, which the CONTAINER_ERROR scenario models.
- Exact Graph error payloads for "publish before finished" / "already published"
  are unverified: the fixture refuses with a message but no cited error code
  (graph_code 0); codes 10/190/4 are the documented ones this lane maps.
- File-size ceilings not encoded (feed-video 650MB is documented but the Reels
  container ceiling was not verifiable in this snapshot) — `max_file_bytes=None`.
- Aspect ratios not encoded in `CapabilityLimits` (single record serves two
  routes: feed 4:5–16:9 vs Reels 9:16); route truths live in the routing rules.
- Service check-order note: `_check_capability` checks disclosures before the
  schedule window, so even a future-window Instagram slot lands
  UNSUPPORTED_DISCLOSURE-held rather than the SCHEDULE refusal — pinned as
  `test_disclosure_hold_precedes_the_schedule_window_refusal`.
- Sibling-lane note for the integrator: T021/T022/T024 test dirs exist in this
  checkout; `test_adapter_matrix.py` basenames collide across lanes under plain
  pytest collection. This lane's test files are instagram-prefixed and its support
  module loads under `instagram_lane_support`, so it is collision-free either way.
