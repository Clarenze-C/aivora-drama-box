## Implementation limits and honest unknowns

- **No live provider exists.** `LiveCommunityProvider` is a named
  PolicyDenied("live community actions disabled until T032") refusal and
  `build_community_service` calls `ensure_mock_mode` (EffectDenied in any other
  mode). Everything runs against the T007 fake in OFFLINE_MOCK under the
  autouse offline network guard.
- **The classifier is deterministic keyword rules, not a model.** It is
  deliberately unmetered (zero cost). A future model-backed classifier or
  reply drafter must reserve METERED_MANAGEMENT through the same
  `_reserve_for_action` path and pass the same `validate_claims` gate; the
  templates are grounded by construction but the gate (not the templates) is
  the enforced defence.
- **Grounding facts are schedule/catalog-shaped only**: released episodes
  (PUBLISHED_VERIFIED posts), announced next (earliest future SCHEDULED slot),
  approved hashtags (scope genre tags + live hashtags), character names.
  `offers` is empty until T026's membership catalog supplies approved offer
  strings — until then ANY price claim is ungrounded (the safe direction).
- **Cooldown semantics chosen**: the 24h cooldown runs between substantive
  EDITS (version ≥ 2); version 1 is the initial publication, so the first
  optimization may run immediately after publish. The edit cap counts
  substantive non-rollback versions v2+ inside the 7-day window. Both choices
  are documented in `_edit_window_gates`; a different ruling is a one-line
  query change.
- **Metadata DEFERRED window**: the version row is created before the provider
  push (durable intent, the T020 pattern — metadata v1 precedes submit there
  too). If the platform push is rate-limited, the local version is applied and
  the action row records DEFERRED + retry window; `retry_deferred` completes
  the push. A permanently abandoned deferral leaves local-ahead-of-platform
  state visible as DEFERRED (never silently reconciled).
- **Event-to-post linking** is by (platform, account_ref, external_post_id)
  against real platform_posts rows; events naming unknown external ids link to
  nothing (platform_post_id NULL) and still get capped per external id.
- **Moderation is limited to MODERATE_HIDE** because that is what the example
  approved policy allows; the confidence gate covers DELETE/REPORT identically
  for any future policy that allows them. Platform capability pinning for
  comment operations (COMMENT_MODERATE etc.) is not modeled — the
  CommunityProvider protocol has no capability surface; see OPEN ITEMS.
