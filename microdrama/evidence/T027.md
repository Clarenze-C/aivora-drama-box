## Acceptance evidence (task_breakdown §5 T027 row)

- **Failed/rejected spend retained**: `cost.season_cost` sums every episode
  account's `settled + accrued + reserved_outstanding + overrun` — a failed
  episode's whole spend stays in the season total and is surfaced per episode
  as `failed_attempt_cost`
  (`test_variable_spend_counts_every_episode_including_failures`,
  `test_failed_spend_is_retained_and_attributed`); recorded overruns count as
  spend, never hidden (`test_recorded_overrun_is_spend_not_hidden`); credits
  are never subtracted (nothing reads them — the budget service itself never
  lets credits restore allowance).
- **Incompatible view definitions do not merge**: `metric_series` refuses
  (Conflict, naming both `version:definition` pairs) when the same metric name
  was recorded under different platform definitions across windows
  (`test_changed_definition_id_across_windows_refuses_merge`,
  `test_changed_definitions_version_refuses_merge`); `traffic_ledger` refuses
  to total a platform+traffic group with mixed definitions versions
  (`test_mixed_definitions_in_one_group_refuse_to_total`); cross-platform sums
  of same-named metrics are never produced — a YouTube "view" and a TikTok
  "view" are different definitions, and comparisons across platforms are
  refused (`test_cross_platform_same_metric_name_is_refused`; the traffic
  report states per-platform totals only).
- **Unknown values remain null**: a metric the platform did not report keeps
  `value=None` end to end — in the stored `metrics` jsonb
  (`test_missing_metric_stays_null_never_zero`), in a traffic total (any
  missing report keeps the group total missing), in hook-ledger rows
  (`test_metric_present_but_value_missing_is_listed_missing`), in the scorecard
  (rendered `—`, never 0), and in `human_review_minutes` (not instrumented
  anywhere in the pipeline yet, so it stays None rather than being guessed —
  `test_human_review_minutes_stay_null_when_unmeasured`, contract-pinned by
  `test_human_review_minutes_may_stay_unknown`).
- **Organic comparisons not labeled causal**: every comparison structure
  carries `causal=False` and the fixed disclaimer verbatim
  (`CohortComparison.__post_init__` REFUSES to be constructed causal;
  `test_same_definition_comparison_is_explicitly_non_causal`,
  `test_disclaimer_is_verbatim`), matching the frozen `HookExperiment`
  `observational_only=True` contract.
- **Streak resets on failed/manual-fixed episode**: a `REJECTED`/`FAILED_*`
  outcome breaks the trailing streak and is recorded in `streak_resets`
  (`test_failed_episode_resets_the_streak`); a published episode that needed a
  human (any `manual_interventions` row) qualifies False and resets
  (`test_manual_fixed_published_episode_resets_the_streak`); the frozen
  contract validator enforces `consecutive == trailing streak` and the DB
  CHECK refuses a QUALIFIED run below ten (both pinned in the contract lane).
- **Management windows pending before day seven**: each published episode's
  window opens at its first verified post and closes seven days later;
  before day seven the window is PENDING with its end recorded
  (`test_window_pending_before_day_seven`), a manual intervention inside the
  window fails it (`test_intervention_inside_window_fails_management`), one
  after the close does not
  (`test_intervention_after_window_close_does_not_fail_management`), an
  in-flight episode has not opened a window (PENDING), a production-failed
  episode never opens one (NOT_QUALIFIED,
  `test_failed_before_publication_never_opens_a_window`); run-level
  management rolls over the last TEN windows exactly as the frozen contract
  requires (`test_nine_clean_episodes_are_not_qualified` pins nine clean
  closed windows still PENDING).
- **Ten episodes required**: one success is never enough
  (`test_one_success_is_never_enough`), nine clean are not a qualification
  (`test_nine_clean_episodes_are_not_qualified`), ten consecutive qualifying
  episodes with ten qualified windows qualify both tracks
  (`test_ten_clean_episodes_qualify`).
- **24h/72h/7d schedules**: windows are schedules, not requests — H24/H72/D7
  snapshots may only be recorded once the boundary (24h/72h/7d after
  `verified_at`) is reached (`test_boundary_gate`, 6 cases including exactly-at
  the boundary); an observation made before the boundary stays refused no
  matter when it is submitted
  (`test_observed_early_but_submitted_late_is_still_refused`); the
  `analytics.snapshot` job handler answers RECORDED summaries for recorded
  windows, WAITING_EXTERNAL for due-but-unrecorded ones (offline there is no
  insights provider to fabricate numbers from), and FAILED for early windows —
  the schedule is not a suggestion (`test_analytics_jobs.py`).
- **Per-platform normalized-with-provenance snapshots**: every stored row
  carries `definitions_version`, per-metric platform definition ids and
  denominators, traffic kind (UNKNOWN kept as its own group), sample count and
  provenance; identical replays are idempotent, divergent re-records are a

  `test_divergent_rerecord_is_conflict_table_stays_append_only`).
- **Hook/source/cohort/denominator ledger**: `hook_ledger` joins the frozen

- **Qualification state persisted append-only**: every evaluation writes one

  the table trigger (`test_run_row_is_persisted_append_only`,
  `test_second_evaluation_is_a_new_run`).

## Lane decisions recorded for the integrator (T029) and later live tasks

1. `human_review_minutes` has no producer anywhere in the pipeline yet; the
   field stays None (unknown) until review-time instrumentation exists — do not
   backfill guesses.
2. Per-episode `failed_attempt_cost` = the whole account spend of a
   non-qualifying episode; attempt-level attribution inside a successful
   episode is not recorded by the budget ledger (receipts are per-operation,
   not per-accepted-output). If finer attribution is ever needed, that is a
   budget-lane change, not an analytics read change.
3. `published_minutes_ms` reads the published FULL_EPISODE master's measured
   duration (`assets.duration_ms` via the verified post); an episode whose
   master has no readable duration contributes no minutes and shows `—`.
4. Management-window failure = any `manual_interventions` row inside the
   seven-day window (a human rescued unattended management). Production
   failure and management failure are separate verdicts by design: production
   can be QUALIFIED while management is still PENDING.
5. Open item from the T025/T026 wave, applied: analytics reads ONLY real
   budget receipts/counters — the synthetic 1000 µ$ DM price and any metered
   management spend appear exactly as the ledger records them, never
   re-estimated.
