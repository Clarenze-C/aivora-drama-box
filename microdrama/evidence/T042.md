## What T042b adds

- `qa/continuity.py` — the actual-media continuity lane: an independent
  media-only `ContinuityObserver` (offline: `FixtureContinuityObserver`, keyed by
  the exported media's own sha256 through the fixture-truth registry, refusing to
  run outside `OFFLINE_MOCK`), a frozen `ContinuityObservation` (digest over media
  sha + evaluator identity/calibration + sampled ranges + windows, verified before
  comparison), per-dimension comparison into timecoded `QAFinding`s, per-check
  coverage records, and the `OFFLINE_FIXTURE_ONLY` calibration runner.
- Check ids: `continuity.{identity,outfit,prop_holder,location_space,
  eyeline_handoff,proof_text}_match` (CRITICAL → `SHOT`; never `CAPTION` — no
  caption-only fix for wrong identity/outfit), `continuity.thai_voice_match`
  (CRITICAL → `LINE`+`AUDIO_MIX`), `continuity.subtitle_safe_area`
  (MAJOR → `CAPTION`+`EDIT`, matching the house severity for caption placement).
  A CRITICAL mismatch blocks release through the frozen `QAFinding.blocks_release`
  rule even though none of these ids is in `CRITICAL_CHECK_IDS` (deliberately
  unchanged — T017 ids stay the configured green gate).
- `qa/service.py` — both observations run inside one metered envelope (a failed
  continuity observation keeps the charge); the run key now binds the continuity
  evaluator capability hash and the typed-expectations digest, so a changed
  calibration, outfit assignment or media sha invalidates a cached run; the run
  event payload carries the bounded continuity evidence block and the per-check
  coverage summary; replays/restarts return the stored findings and coverage.
- `testing/media.py` — `ContinuityTruthWindow` declarations on `FixtureTruth`, the
  labeled continuity defect suite (clean + identity/outfit/prop-holder/location/
  eyeline/proof-text/thai-voice/subtitle-safe-area) and the clean expectations
  builder. Each fixture's bytes embed a digest of its declared truth, so the
  comparison always runs against the actual exported media SHA.
- Honesty rules preserved: `PASS` requires `CHECKED`; unobserved/unsampled/
  uncalibrated/unavailable dimensions are `UNKNOWN`; a still-frame (T042a) PASS
  never certifies these motion checks — every finding cites an observed media
  window of the exported bytes.

## Calibration (OFFLINE_FIXTURE_ONLY)

`run_continuity_calibration` over the 9-case labeled set reports, per check id:
applicability (cases), TP/FP/TN/FN, unknown cases and per-window coverage counts;
plus applicability by shot class derived from the expectation windows' own
`shot_class` (prop/proof checks apply only to the two-handed scene class). Current
matrix: every check TP=1 (exactly its seeded defect), TN=8, FP=0, FN=0; the
report is deterministic and hard-labels `label=OFFLINE_FIXTURE_ONLY`,
`live_activation_enabled=False`. These scores verify software behavior on declared
fixture truth only: they cannot qualify a real vision/ASR model or claim measured
real-world accuracy, and no live release gating may be derived from them (T031
owns real-model evidence; the offline observers refuse non-OFFLINE_MOCK modes).

## Contract gap — guardian proposal (per-check coverage)

The canonical `CoverageWindow` (`contracts/qa.py`) carries `check_family` only;
it cannot distinguish checks inside one family, so the eight continuity checks
sharing `VISUAL_IDENTITY`/`TEMPORAL`/`AUDIO`/`CAPTION` cannot each carry honest
coverage through the frozen contract. T042b does NOT edit the frozen contracts
and does NOT claim family-level windows distinguish checks. It persists a
bounded QA-local per-check coverage record instead:

- `qa.models.CheckCoverageWindow` (module-local, `asset_id`+`check_id`+range+status),
- `summarize_check_coverage` (bounded, 16 KiB event cap) onto the
  `qa.technical.completed` run event payload,
- `load_run_check_coverage` reads it back on replay/restart; run events written
  before T042b replay with an empty per-check list.

**Proposal to the contracts guardian:** extend `CoverageWindow` with an optional
`check_id: Identifier | None` (family-level when absent), or add a check-level
coverage artifact to the QA contract family, and consider whether
`CheckFamily` should grow a `CONTINUITY` member. Until accepted, the QA-local
record is the only per-check coverage authority and nothing outside the QA lane
consumes it. No enum or migration was invented in a QA module.

## Scoped review fixes — 31 October 2026 (T042b fix round)

Four findings from the parent review, fixed on the same dirty checkout; nothing
staged, committed or deployed, no provider call, no canonical contract touched.

1. **Forged observation binding** (`qa/service.py` `_observe`,
   `qa/continuity.py` `continuity_findings`): the run key bound the *configured*
   observer's evaluator capability, but a returned `ContinuityObservation` could
   declare a different `media_sha256` or evaluator and still green the asset.
   Now the returned observation is validated inside the metered observation
   step, before successful settlement: `media_sha256` must equal the staged
   asset sha256 and the returned evaluator capability hash must equal the
   configured observer's. A mismatch settles through the failed-observation
   path (`_settle_failure`, charge kept, `ProviderError`, no persisted QA
   claim), and `continuity_findings` independently refuses an observation keyed
   to other bytes (`SchemaInvalid`) so direct callers are covered too. Tests:
   a forged observer returning the clean fixture's windows for the defective
   asset (charge kept, zero findings/events, honest rerun is a fresh COMPLETED
   run — nothing replayed) and one returning a different evaluator's stamp.
2. **Expectations seam binding** (`qa/service.py` `run_episode_qa`,
   `qa/continuity.py` `EpisodeContinuityExpectations.validate_binding`): the
   seam could return another episode's payload, or windows beyond the media.
   `validate_binding(episode_id, media_duration_ms)` rejects a mismatched
   episode id or any window ending past the measured exported-media duration
   (the descriptor's registered probe of the sha-verified staged bytes) BEFORE
   the run key is derived — so nothing is compared and nothing is cached under
   a wrong digest. The test worlds now bind their stub payloads to the seeded
   episode (the old random-episode stubs were themselves the vulnerability).
   Tests: cross-episode payload and an out-of-range window are refused with
   zero observer dispatches and no persisted rows; the bound payload then runs
   fresh.
3. **Paid-mode observer refusal** (`qa/service.py` `run_episode_qa`): only
   `FixtureContinuityObserver` refused non-OFFLINE_MOCK; an arbitrary injected
   observer could run in PAID_BENCHMARK and produce green continuity findings
   with no real-model qualification. Now ANY configured continuity observer is
   refused with a typed `EffectDenied` at the top of `run_episode_qa` — before
   any reservation, provider call or replay. A no-observer paid path remains
   honest UNKNOWN (continuity checks UNKNOWN/UNAVAILABLE and never blocking;
   the V1 critical checks keep their own honesty). Tests: a recording fake
   observer in PAID_BENCHMARK sees zero calls, raises `EffectDenied`, leaves no
   reservation or findings; the no-observer paid run completes honestly.
4. **Evidence path**: this file was at the repo-root `evidence/T042.md`; it now
   lives at the established `microdrama/evidence/T042.md` path (the
   `qa/continuity.py` docstring reference updated to match).
