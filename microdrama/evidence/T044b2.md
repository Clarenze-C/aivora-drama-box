Branch `feat/microdrama-m0-m4`, dirty uncommitted checkout, 1 November 2026 UTC. T044b2 is **partial T044 work** (the intake half), not owner-workbench acceptance; the parent review plus full `make check`/`make pilot` under CPUQuota45% remain before T044 closes.

## What was built

- `review/intake.py` (new): `IntakeService` + `IntakeConfig` + the closed wizard form parsers. The owner UI asks exactly three questions (story idea, genre/tone, episode count 1–10). `check_form_fields` rejects every other posted name loudly, so a browser cannot submit a `SeasonScope`, cost policy, destinations or management policy, and the generated scopes carry the configured template's policy byte for byte (pinned by test).
- One wizard submission is one idempotent command (`IdempotencyService`, scope `POST /ui/intake`, key = the one-time wizard key minted on the first page). Inside that ONE transaction: the PROPOSED season row, `review.scope.link_season_creator` (T044a), the sealed `ConceptIntake` V2 document (deterministic `uuid5` intake→season link, exact `content_sha256`) and — when configured — the pre-Gate-1 research envelope. Candidate work happens only later, behind the frozen `research.collect_and_propose` job; no browser request waits through generation.
- Fail-closed configuration: with no configured envelope, scope template, source lane, model, token prices, or live paid-request authorization, the submission is recorded, the status page reports the typed blocker list and NO job is dispatched (no default positive spend in any live mode — the envelope default is `None`, and the only positive default (US$2 synthetic) is wired in the OFFLINE_MOCK pipeline world where `build_fake_providers` refuses non-mock settings). "Rights" at candidate stage stay PENDING by contract design (`PendingRightsAssessment`); the rights-shaped dispatch blocker is the live-mode paid-authorization switch, labelled as such.
- The background handler (`IntakeService.handle_research_job`, registered through `pipeline/handlers.py` on the `owner_intake`/`owner_selection.<uuid>` triggers; scheduled pilot triggers keep the mock request) reuses `ScriptMakerService.generate_candidates` and `ResearchService.run_research` unchanged, persists hash-sealed `ConceptCandidate` documents (append-only consecutive versions, identical replays skipped), and lets the bounded research run write the current Gate 1 proposal. The status page shows every candidate with pending rights, originality verdict/rank and research uncertainty/evidence.
- Owner selection: `select()` enqueues one more bounded run restricted to the chosen candidate; the run persists the next proposal version and the selected candidate's document is rebound (next version) to the exact persisted scope hash — the hash the existing Gate 1 page binds. Selecting the candidate the current proposal already binds is a typed replay (200 REPLAYED, no job, no spend). Silence approves nothing; Gate 1 remains the only human concept decision (exactly one `approval_events` row after approval). Selection after Gate 1 is refused typed.
- Workbench (`/ui/seasons/{id}/workbench`): read-only, owner-scoped projection of current typed V2 documents (SeasonStoryLedger, CharacterLogic, SecretLedger, StyleBible, WardrobeBible, EpisodePack, DirectingManifest sections/shots, SceneWardrobeAssignment, PromptManifest, PropSheet, LocationLayout, AssetSheet), each hash-verified on read with honest unknown/missing/ambiguous labels; wardrobe assets link through the existing owner-scoped `/ui/media/{asset_id}` stream. No new asset ledger, no stored progress counter.
- Wiring: `review/api.py` registers the wizard/status/selection/workbench routes only when an `IntakeService` is passed; `api/compose.py` carries it as optional integrator wiring; the OFFLINE_MOCK pipeline world composes `build_script_maker_service` + `IntakeService` with labelled mock defaults.

## Known gaps (honest)

- Builder-found defect during self-review, fixed and pinned: the first persistence draft compared candidate documents including the `version`/`updated_at` fields, so repeated handler replays would have appended endless candidate versions (and a stale intake replay could regress the selected candidate's current document to its raw hash). Persistence now (a) inserts each generated candidate only once (append-only raw history), (b) re-versions only the one candidate a run actually bound to a persisted proposal, comparing a content fingerprint that excludes versioning metadata, and (c) never un-binds the candidate the CURRENT proposal is bound to. The composed test asserts a stale intake-job replay after a selection appends zero candidate rows and the live binding survives.
- The last full `make check`/`make pilot` receipt predates this build; the parent runs them (with independent review) before T044 acceptance.
- Durable replay of candidate generation relies on the frozen mock clock: with a live wall clock the reservation request hash (expiry) changes across restarts, so a crashed live generation retries as new attempts inside the same envelope. This is the pre-existing integrator caveat documented in `research/script_maker.py` ("durable replay … is the integrator's persisted intake record"); a live-mode durable generation store is T046/T047 wiring work, and in OFFLINE_MOCK (this build's only dispatching mode) replay is exact and covered by tests.
- Two rapid different selections enqueue two bounded runs; the last completed run's proposal is current, and Gate 1 always binds the current proposal hash under `StaleRevision` protection.
- The Gate 1 page after selection still renders whatever proposal is current; a dedicated "your selection is being prepared" interstitial is cosmetic future work, not a safety gap (the job table on the status page shows the queued selection run).

## Review fix round — 1 November 2026 (same day, after Codex scoped review)

The interrupted build was reviewed independently (Codex xhigh, scoped to this
delta; findings in `docs/microdrama-system/T044b2-codex-review.md`): 5 BLOCKING,
1 NON-BLOCKING, verdict "do not close as-is". All six were verified against the
code and fixed in-session (Codex weekly quota nearly spent; the operator directed
the session reviewer to fix and re-review — same-model caveat noted):

1. **Selection replay (BLOCKING, fixed).** `select()` keyed selection jobs and
   research trigger keys by candidate only, so B→A→B replayed B's first
   completed job and the proposal stayed on A. Selections now carry a durable
   revision (count of prior selection jobs, serialized by the existing season
   `FOR UPDATE`): semantic key `intake-selection:{season}:{rev}`, trigger
   `owner_selection.{rev}.{candidate}`, research key
   `script-maker.select:{intake}:{cid}:{rev}`. The latest intent is identified by
   the highest embedded revision (job id/created_at order is not reliable under
   the frozen mock clock). A double-click while the run is queued dedupes to the
   same job; a completed same-candidate selection that already binds the proposal
   stays a typed replay. Pinned by
   `test_reselecting_after_another_selection_reruns_the_candidate`.
2. **Cross-owner sheet leakage (BLOCKING, fixed).** PropSheet/LocationLayout/
   AssetSheet carry no season field and their ids are shared identifiers, so the
   workbench's global queries could show another owner's record ids and
   `rows[-1]` guessed on multiplicity. Sheets are now proven by asset
   provenance: PropSheet/AssetSheet via `assets.season_id` (migration 0004),
   LocationLayout via `geometry_sha256` equality with a season-proven
   location-role AssetSheet (both are minted from the same empty-plate asset).
   Ambiguous proven matches are honest unknowns. Pinned by
   `test_workbench_refuses_unverified_documents_and_foreign_sheets`.
3. **Silent source-lane skip (BLOCKING, fixed).** A missing/disabled source
   provider or unconfigured research prices silently skipped research steps
   after generation spent. `IntakeService._blockers()` now reads the composed
   `ResearchService`'s live registry (`enabled`, `disabled_reason`) and config
   (search + LLM prices, LLM presence) before dispatch; a public `llm` property
   was added to `ResearchService`. Pinned by
   `test_unregistered_source_provider_blocks_dispatch`.
4. **Unverified display values (BLOCKING, fixed).** SceneWardrobeAssignment and
   PromptManifest summaries (and the wardrobe media link) were built from raw
   payloads; raw EpisodePack scenes steered the prop/location lists. All three
   are now model-validated AND hash-verified before any field is used; failures
   are unknowns and the media link disappears. Pinned by the same workbench test
   (tamper arrives as a fresh INSERT with a stale hash — `payload` is immutable
   by trigger).
5. **Unverified scope as canon (BLOCKING, fixed).** The workbench now checks
   `canonical_hash(scope) == season_proposals.scope_hash` before showing arc and
   cast, and the template heading no longer claims "Approved scope" for a
   PROPOSED row — the status chip carries the real status. Pinned by the same
   test (tampered v2 proposal with v1's stale hash).
6. **Hidden blockers (NON-BLOCKING, fixed).** The status page computes CURRENT
   configuration blockers on every read; with jobs recorded they render under
   "Configuration problems present now" instead of disappearing. Pinned by
   `test_status_shows_current_blockers_alongside_recorded_jobs`.

Also added: a typed `CANDIDATE_GENERATION_EMPTY` failure instead of an
IndexError if a COMPLETED generation ever returns no scopes (Codex seeded check
(b), defensive edge).
