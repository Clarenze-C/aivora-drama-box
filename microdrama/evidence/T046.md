## Defects the drill itself caught (and fixed)

- **Restart crash (P1, fixed + pinned):** `seed_mock_catalog` re-recorded
  version-1 presets on every boot — a second boot against a durable database
  Conflict-crashed. Seeding is now guarded by preset-catalog presence;
  regression-pinned in `tests/unit/api/test_serve_entries.py`.
- **Deterministic ids in a durable process (P1, fixed):** the world defaulted
  to `SequentialIds("pipeline")`, so `create-owner` worked exactly ONCE per
  database (second owner hit `owners_pkey`). The durable entries now pass
  `UuidIds()`.
- Drill-script fixes (port sourced from staging.env, `--username` flag,
  per-run owner identity, restore-stack login base URL) — script-only.

## Independent stand-in review fix round — 2 November 2026

Cross-model review (Claude Sonnet 5.5 read-only, Opus rulings) stood in for
the pending Codex review: `docs/microdrama-system/T044b2-T046-T047-claude-review-2026-11-02.md`,
findings DB-7/DB-10/DB-11. All rulings BINDING.

**DB-7 — STAGING_APP_PORT defaulted to 8091 (arisa-sfw-review's port).**
Defaults are now 8093 in `deployment/compose.staging.yaml`,
`staging.env.example`, `DOMAIN-RUNBOOK.md` and the drill script (its own
default also said 8091; the drill itself already ran on 8093 via
`staging.env`). Historical drill logs and the runbook's 8093 forwarder text
are unchanged (receipts).

**DB-10 — first-boot seeding was read-then-seed.** Two first boots could
interleave, and a crash after the preset catalog committed left a half-seeded
database the guard then skipped forever. Check + seed now run under a
dedicated PostgreSQL advisory lock (`Database.advisory_lock`,
deterministic `FIRST_BOOT_SEED_LOCK_KEY`, held on its own connection so the
pool stays usable) and the catalog + registries seed inside ONE transaction.
The three registries' `record()` accept an optional caller-owned `Tx`
(default behavior unchanged). Pinned by
`test_first_boot_seed_is_atomic_when_it_fails_midway` (red before: presets
survived the simulated crash; green: zero rows after the crash, clean retry
seeds catalog AND mock rights) and
`test_first_boot_seeding_holds_the_first_boot_advisory_lock`
(`pg_try_advisory_xact_lock` from another session fails while seeding runs).

**DB-11 — serve-entry hardening.** `create-owner` writes the password file
via `os.open(O_CREAT|O_EXCL, 0o600)` — no umask window, and an existing file
fails loudly (exit 4) instead of being overwritten. `health` now requires
the payload to report `status: ok`, not just HTTP 200. Pinned by
`test_secret_file_is_created_0600_and_never_overwritten` and
`test_health_fails_when_the_payload_is_not_ok` (both red before: `_health`
returned 0 for a not-ok payload; `_write_secret_file` did not exist).
