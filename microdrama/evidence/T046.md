**DB-10 — first-boot seeding was read-then-seed.** Two first boots could
interleave, and a crash after the preset catalog committed left a half-seeded

dedicated PostgreSQL advisory lock (`Database.advisory_lock`,

The three registries' `record()` accept an optional caller-owned `Tx`

`test_first_boot_seed_is_atomic_when_it_fails_midway` (red before: presets
survived the simulated crash; green: zero rows after the crash, clean retry
seeds catalog AND mock rights) and
`test_first_boot_seeding_holds_the_first_boot_advisory_lock`
(`pg_try_advisory_xact_lock` from another session fails while seeding runs).

**DB-11 — serve-entry hardening.** `create-owner` writes the password file
via `os.open(O_CREAT|O_EXCL, 0o600)` — no umask window, and an existing file
fails loudly (exit 4) instead of being overwritten. `health` now requires
the payload to report `status: ok`, not just HTTP 200. Pinned by
`test_secret_file_is_created_0600_and_never_overwritten` and
`test_health_fails_when_the_payload_is_not_ok` (both red before: `_health`
returned 0 for a not-ok payload; `_write_secret_file` did not exist).

## Re-review round 2 fixes (DBR-1, DBR-3, drill re-run) — 2 November 2026

Re-review 1 of the fix round (same review file) accepted with three
follow-ups on this task's surface; all fixed tests-first.

**DBR-1 — `create-owner` reserved its password file too late.** The owner
row committed BEFORE the `--write-password-to` target was opened, so an
existing target meant exit 4 with the owner created and the one-time
password lost — an owner nobody could ever log in as. Now `_open_secret_file`
(`O_CREAT|O_EXCL`, 0600 — the DB-11 primitive, renamed because the open and
the write now happen at different times) reserves the target BEFORE
`world.auth.create_owner`; an existing target is exit 4 with ZERO owner rows
and the file untouched; a failed creation closes and unlinks the empty
reservation and re-raises; the password is written into the already-open fd
only after the row exists. Pinned (unit, real Postgres) by
`test_create_owner_refuses_an_existing_password_file_and_creates_no_owner`
(red before: `assert 1 == 0` — the owner was created),
`test_create_owner_writes_password_0600_to_a_fresh_target` and
`test_create_owner_failure_after_the_reservation_leaves_no_file_and_no_owner`
(both green pins of the new order). The DB-11 unit test now exercises the
renamed `_open_secret_file` (same O_CREAT|O_EXCL 0600 semantics).

**DBR-3 — `Database.advisory_lock` could wait forever.** The lock connection
now runs `SET lock_timeout` (default 120 s, `timeout_s=` per call) before
`pg_advisory_lock`; `LockNotAvailable`/`QueryCanceled` map to a typed
retryable `ServiceUnavailable` naming the key ("advisory lock <key> not
acquired within <n>ms") instead of an unbounded hang. Non-positive or
non-finite timeouts are refused locally. Pinned (integration) by
`test_advisory_lock_times_out_with_a_typed_error` in
`tests/integration/persistence/test_migrations.py`: another session holds
the key, the caller asks for 0.5 s, the typed error fires (red before:
`TypeError` — no timeout parameter existed; the unbounded wait itself cannot
be shown red without hanging a runner).

Receipts (CPUQuota45%): `test_serve_entries.py` **11/11** (3 new);
`test_migrations.py` **10/10** (1 new). The DBR-6 drill re-run is recorded
in the next section.
